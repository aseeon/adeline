# Adeline 0.1.10

This release rebuilds how Adeline talks to agents. It now runs on the official Agent Client Protocol (ACP) SDK, so agents behave more predictably and Adeline can use more of what they offer. On top of that come install and login for the supported agents, menus for each agent's own settings and modes, a message queue, attachments, the agent's TODO list, MCP servers, and an ACP traffic view. All since 0.1.6.

## Before you upgrade

- **Your chats start fresh.** Chats saved by earlier versions stay on disk, untouched, but Adeline no longer shows them. Agent definitions and projects carry over.
- **Permission modes are gone.** Ask, Allow reads and Allow everything are replaced by the agent's own modes (see below). A saved permission mode is ignored, and dropped the next time you save the agent.
- **Remote machines need 0.1.10 too.** The engine protocol changed, so Adeline upgrades the Adeline on each remote machine when it connects. As before, it asks first if that machine's engine is running agents.

## Supported agents

Adeline now knows these agents and how each one works:

- **Claude**, through `@agentclientprotocol/claude-agent-acp`
- **Codex**, through `@agentclientprotocol/codex-acp`
- **Pi**, through `pi-acp` and the `pi` CLI
- **opencode**
- **OMP**

Other ACP agents still work as custom agents.

- **Install.** For a supported agent that isn't installed, the agent form offers to install it with the agent's standard global install (`npm install -g`, or the vendor's installer for opencode and OMP). It shows the exact commands first, runs them only after you confirm, and streams their output. A failed install keeps its output and offers Retry.
- **Node.js.** If an agent needs Node.js and it's missing, Adeline offers to install it with winget on Windows or Homebrew on macOS. Without either, it links to nodejs.org.
- **Updates.** When an installed agent is older than the latest published version, Adeline offers an update. It never updates on its own.
- **Login.** When an agent needs you to log in, in the agent form or mid-chat, Adeline offers the agent's own login methods. It opens the agent's login page in your browser or runs its login command in your terminal, and offers Log out where the agent supports it. Logins are never retried automatically.
- **Optional.** An agent you installed or logged in to yourself works the same.
- **Remote machines.** Install, update and login run on the machine the agent runs on, with that machine's own methods.
- **System instructions.** These now reach Claude too. The instructions field only shows for agents that can take them (Claude and OMP).

## Chat settings menus

The message box has Model, Effort and Mode menus, plus a More options menu for anything else the agent offers, like Claude's fast mode or output style.

- They list what the running agent actually offers, with each option's description.
- A change applies to the running session and to this chat only, never to the agent's defaults.
- A chat whose agent isn't running shows the options from its last session, and your choice applies when the agent starts again.
- The menus are disabled while a turn runs. If the agent changes a setting itself, the menu shows the new value.
- The agent form gains a default Mode, next to its default model and effort.

**Modes replace permission modes.** The agent's own modes, such as Claude's "Accept edits", decide what it may do without asking. Plan modes are left out of the menus. Permission requests show the agent's own choices, except "reject always".

## Sending while the agent works

The message box is never blocked by a running turn.

- **Queue** holds your message until the turn ends. Queued messages appear under the turn, where you can edit, remove or send each one now. Up in an empty message box takes the last one back to edit. When the turn ends, everything queued goes as one message.
- **Send now** delivers the message straight away. Agents that support steering get it mid-turn. With others, Adeline stops the turn and sends it as the next message.

## What the agent is doing

- **Activity.** The line under the chat says what is happening, from what the agent reports: Thinking, Reading, Writing, Running commands, Using tools, Waiting for your permission, or Quiet.
- **Hang notice.** When a turn has been silent for 10 minutes with nothing open, Adeline says so and offers Stop and Restart. It never ends a turn on its own. Change the time, or turn the notice off with 0, in Settings › Chats.
- **TODO list.** The agent's TODO list shows in the chat header as the current step and a count, like "3 of 4". Open it to see every step and its status. It stays with the chat across restarts.
- **Thinking.** A new "Show thinking" setting in Settings › Chats streams the agent's thoughts into the chat, folded under "Thought for 12s". It is off by default.
- **Titles.** Chat titles come from the agent when it provides one.
- **Crashes.** An agent that exits mid-turn shows an error in that chat only, with the agent's last output. Each chat runs its own agent process.
- **Errors clear themselves.** An error under a chat goes away once a later turn starts, and the × next to it hides it by hand.

## Attachments and commands

- **Attach files** by picking, dropping or pasting them. Images go as images when the agent supports them. Other files go as embedded content, or as a file link when the agent can't take embedded content. Files over 20 MB are refused with a clear message.
- **Commands.** Type `/` at the start of the message box to list the agent's commands, with descriptions and input hints. Up and Down move, and Enter or Tab inserts.

## MCP servers

Settings has a new MCP servers page for servers every agent gets, and the agent form has its own list for that agent. A server is a command (with arguments and environment variables) or an HTTP URL (with headers). A server the agent can't use is skipped, with a note in the chat.

## ACP traffic

The side panel has an ACP traffic tab next to Agent activity. It shows every message between Adeline and the agent, plus the agent's error output. Lines that aren't valid ACP are marked "not JSON" or "unknown". Copy all, or copy one message, to report a problem.

## Keyboard shortcuts

| Shortcut | Action |
|---|---|
| Ctrl+Shift+Enter (Cmd+Shift+Enter) | Send now |
| Ctrl+. (Cmd+.) | Stop the turn |
| Ctrl+Shift+R (Cmd+Shift+R) | Restart the agent |
| Alt+M, Alt+E, Alt+O, Alt+P (Cmd+Shift+M, E, O, P) | Model, Effort, Mode and More options menus |
| Ctrl+Shift+A (Cmd+Shift+A) | Attach files |
| Ctrl+Shift+L (Cmd+Shift+L) | ACP traffic |
| Ctrl+Shift+T (Cmd+Shift+T) | TODO list |

The menus use Alt on Windows and Linux because tools like AMD Adrenalin take Ctrl+Shift+M, E and O for themselves. The full list is in [docs/shortcuts.md](https://github.com/aseeon/adeline/blob/main/docs/shortcuts.md).

## Other changes

- **macOS app.** macOS now ships as `Adeline.app` instead of a bare executable, with an icon and a menu bar (Adeline, File, Edit and Window).
- **Send button.** With "Submit on Enter" off, the send button shows the Ctrl key (Cmd on macOS) it needs.
- **Machine name.** The local machine is named after your computer's hostname instead of "Local machine".
- **Remote versions.** A remote machine is kept whenever its engine speaks the same protocol, whatever its Adeline version. Only a missing install or an older protocol replaces it.
- **Stopping agents.** Force Stop and engine shutdown end the agent's whole process tree, including processes started through npm shims.
- **Faster saving.** Streaming replies are saved in batches, so long replies cost less disk work.
- **Demo.** `--demo` shows the new features with sample content: a TODO list, queued messages, a stalled turn, ACP traffic, a thought and an attachment.

The new client was tested end to end against a scripted fake agent, and with Claude in daily use. Codex, Pi, opencode and OMP have had less real-world use, so please [report](https://github.com/aseeon/adeline/issues) anything that doesn't work with them.
