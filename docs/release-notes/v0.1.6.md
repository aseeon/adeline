# Adeline 0.1.6

This release lets one Adeline window show and drive projects on several computers at once, and adds a headless build for servers. It also adds forking, safer auto-approval, and better agent detection, all since 0.1.0.

## Remote machines

Adeline can now connect to your other computers over SSH. Run agents on a desktop at home or on a server and drive them from a laptop elsewhere: send prompts, answer permission requests and watch replies stream in, as if the projects were local.

- **Adding a machine.** Open Settings, choose "Add machine…" in the machine dropdown at the bottom of the sidebar, and give it a name and an SSH destination. A destination is `user@host`, `user@host:port` or a `Host` alias from your `~/.ssh/config`. A machine can have several destinations, such as one for your home network and one for outside it. Adeline tries them in order.
- **The machine selector.** Once you save a remote machine, a selector appears in the title bar. Check any combination of machines, including this one, to see their projects side by side. With more than one machine checked, tabs and the projects menu show which machine each project is on. Each machine also shows its state there, and the error behind it.
- **Everything stays on its machine.** Conversations, agents and engine settings live on the machine that runs them. Nothing is copied between machines. Settings shows the Agents and Engine pages of whichever machine you pick in its dropdown.
- **Folders on the other machine.** "Open folder…", the New project dialog and "Add a file" browse the remote machine's folders when the project is on a remote machine.
- **Dropped connections.** When a connection drops, the machine's projects stay on screen as they were, read-only, and Adeline reconnects in the background. When it's back, you get only what you missed, and a reply that was still streaming carries on.
- **Sign-in.** Adeline uses your system `ssh`, keys and SSH agent, and opens no network port anywhere. Password prompts and unknown host keys appear in Adeline dialogs. Adeline never stores passwords, and it refuses a host whose key has changed.
- **Installing and upgrading.** If the other machine has no Adeline, or an older one, Adeline installs its own version there from the GitHub release. It installs the headless build (see below), so a server with no desktop works without extra libraries. It never downgrades. If the other machine's engine is running agents, Adeline asks before restarting it with the new version. Supported remote machines are Windows (x86_64), macOS (Apple Silicon) and Linux (x86_64 and ARM64).

This is the first release with remote machines. It was tested against simulated machines, not yet against real SSH servers on every platform. Please [report](https://github.com/aseeon/adeline/issues) anything that doesn't connect.

## Headless build

Each release now has a headless build next to the desktop zips:

- `adeline-headless-windows-x86_64.zip`
- `adeline-headless-macos-arm64.zip`
- `adeline-headless-linux-x86_64.zip`
- `adeline-headless-linux-aarch64.zip`

Each holds one `adeline` executable with no window. It runs `adeline engine`, `adeline bridge` and `adeline --version`, and needs no desktop or GPU libraries, so it runs on a bare VPS or a home server. The Linux builds are static and run on any distribution, Alpine included. `adeline --version` shows `(headless)` after the version, and Settings › Engine shows whether the selected machine runs the headless or the full build.

You don't need to download it yourself: Adeline installs it on the machines you add. Take it only to set up a server by hand.

## Fork a conversation

Every finished reply has a Fork button. It copies the chat up to that reply into a new chat in the same project, with the same agent settings, and links back to where it came from. When the agent supports it, the fork continues the agent's own session. Otherwise Adeline gives the agent the history as text and says so in the chat.

## Safer auto-approval

Commands like `rm -rf`, `git push --force` and `git reset --hard` now always ask for your approval, even when the permission mode allows everything. This is a basic safety net, not a sandbox.

## Agents

- Adeline now finds installed npm and uv agents by reading their package metadata, so agents whose command name differs from the package name, like MiniMax Code's `mcode`, show as installed. An unrelated program with the same name, like VS Code's `code`, is no longer mistaken for an agent.
- On macOS and Linux, each agent runs in its own process group. Agents now stop when the engine exits, including ones left behind by an engine that crashed.

## Other changes

- Retrying a forked chat whose first turn failed starts a fresh session and sends the history again.
- In `--demo`, the sample projects are spread across three demo machines, one of them shown disconnected.
- The "Machine selector" feature toggle in Settings is gone. The selector now appears on its own once you save a remote machine.

## Getting it

Download the zip for your platform from the [release page](https://github.com/aseeon/adeline/releases/tag/v0.1.6): `adeline-windows-x86_64.zip`, `adeline-macos-arm64.zip` or `adeline-linux-x86_64.zip`. Adeline is early. Expect rough edges and breaking changes.
