# Tech debt in 0.1.2

These are known shortcuts in the code as of v0.1.2. Each entry says where the shortcut is, what it can't handle, and when to fix it. Entries without a known trigger are marked "No trigger yet". Decide on those before they're forgotten.

## Engine and agents

### Agents can outlive the engine on macOS and Linux

`contain_children` in `src/platform.rs`.

On Windows, a Job Object ties every agent process to the engine, so they all die when the engine dies. On macOS and Linux the function does nothing. Agents only notice the engine is gone when their stdin closes, so an agent that ignores that keeps running.

When to fix: as soon as Adeline is developed on macOS. On Linux, `PR_SET_PDEATHSIG` solves it. macOS has no equivalent, so it needs another approach, such as a watchdog that checks the parent PID or a process group the engine kills on exit. A macOS port of the engine checks would cover this with AC1 ("agents are engine children and die with it").

### Retry doesn't resend a text-copy fork's history after a failed first turn

`fork_history` in `src/engine.rs`.

A fork only gets its copied history if it has no agent session yet. Say the agent has no native `session/fork`, the session starts, and then the first turn fails for good. Retry then sends the prompt without the history, so the agent loses the earlier conversation.

When to fix: if this shows up in use. The fix is to record per fork whether the history was delivered, and resend it until it was.

## Permissions

### Always-ask commands are matched by substring

`PROTECTED` in `src/acp.rs`.

Commands like `rm -rf`, `git push --force` and `git reset --hard` always need your approval, even when the permission mode allows everything. The check looks for these strings in the tool call's title and input. Quoting, extra spaces, aliases or a script that wraps the command can get past it. It's a minimum check on top of auto-approval and doesn't sandbox anything.

No trigger yet. Revisit if a destructive command ever runs without asking, or before advertising "Allow everything" as safe.

## Agent setup

### Installed-agent detection guesses the binary name

The `npx`/`uvx` loop in `src/harness.rs`.

For an npm or uv package, Adeline guesses the executable from the package name. For example, `@scope/name@1.2.3` becomes `name`, and `name-cli` also becomes `name`. Packages whose binary has a different name show as not installed even when they are.

No trigger yet. Revisit when a registry agent shows as missing although it's installed. The fix is to read the binary name from the package's own metadata, or to add an override in the agent definition.

## UI

### Agent avatars are looked up on every render

`Adeline::agent_icon` in `src/chat_render.rs`.

Each render searches the agent catalog for the agent and builds its avatar path again.

When to fix: if chat lists get slow with many chats or agents. Cache the path per agent and clear it when the catalog changes.

## Windows

### Agent stdio pipes use the default access list

`overlapped_pipe` in `src/platform.rs`.

The named pipe for an agent's output gets Windows' default security descriptor (DACL). It's safe today because the pipe allows one instance, rejects remote clients, and Adeline connects to it right after creating it, so nothing else can get in first.

No trigger yet. Revisit if the pipe ever allows more instances or stays open before Adeline connects. Then give it an owner-only DACL, like `owner_only_pipe` does for the engine pipe.
