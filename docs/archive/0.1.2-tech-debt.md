# Tech debt in 0.1.2

These are known shortcuts in the code as of v0.1.2, updated in v0.1.3. Each entry says where the shortcut is, what it can't handle, and when to fix it. Entries without a known trigger are marked "No trigger yet". Decide on those before they're forgotten.

## Permissions

### Always-ask commands are matched by substring

`PROTECTED` in `src/acp.rs`.

Commands like `rm -rf`, `git push --force` and `git reset --hard` always need your approval, even when the permission mode allows everything. The check looks for these strings in the tool call's title and input. Quoting, extra spaces, aliases or a script that wraps the command can get past it. It's a minimum check on top of auto-approval and doesn't sandbox anything.

No trigger yet. Don't make the matcher smarter: any blocklist can be bypassed. If "Allow everything" ever needs to be safe, sandbox the agent (worktree, container or restricted user) instead.

## Agent setup

### Installed-agent detection guesses the binary name

The `npx`/`uvx` loop in `src/harness.rs`.

For an npm or uv package, Adeline guesses the executable from the package name. For example, `@scope/name@1.2.3` becomes `name`, and `name-cli` also becomes `name`. `comes_from` only accepts a guess whose shim or link points into the package, so a different program with the same name, like VS Code's `code` for `@minimax-ai/code`, isn't mistaken for the agent. Packages whose binary has a different name, like MiniMax's `mcode`, still show as not installed even when they are.

No trigger yet. Revisit when an installed registry agent shows as missing. The fix is to read the binary name from the package's own metadata (its `package.json` `bin`), or to add an override in the agent definition.

### Agents whose group leader exited can outlive the engine on macOS and Linux

`stop_groups` in `src/platform.rs`.

Each agent runs in its own process group, which the engine kills on exit, or the next engine kills if this one crashed. To avoid hitting an unrelated process that reused the ID, a group is killed only if its leader still runs the program Adeline started. If the leader has exited but its children haven't, those children are left running.

No trigger yet. Revisit if orphaned agent processes turn up on macOS or Linux. Then find the group's members with `ps -g` instead of checking the leader.
