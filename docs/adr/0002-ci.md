# CI

CI (`.github/workflows/ci.yml`) follows Zed's `run_tests` workflow: a fast style check, then clippy and tests on every OS, a dependency check, and one `tests_pass` job that branch protection requires. Actions are pinned to commit SHAs.

## When CI runs

Pushes and pull requests that only touch docs, Markdown or agent skills skip CI. A push with any other file runs it, whatever the commit order, so commits need no `[skip ci]`.

## Warnings are errors in CI only

`.cargo/ci-config.toml` is copied from Zed's approach. CI copies it to `../.cargo/config.toml`, where Cargo merges it with the repo's config. Local builds stay tolerant of warnings, and CI turns every warning into an error.

- It avoids `RUSTFLAGS`, because that variable replaces every other `rustflags` setting (rust-lang/cargo#5376).
- It sets `[target.'cfg(all())']` instead of `[build]`, because target `rustflags` add up while `[build]` ones replace each other.

## Test steps

- Linux installs lavapipe, Mesa's software Vulkan driver, so the pixel tests render on wgpu.
- The headless build is built before the tests, for the UI test that installs it on a fake remote machine.
- Tests that download an old release run in their own step (`--run-ignored only`), off the main step's network path.
- `cargo deny` checks every crate in `Cargo.lock` against the RustSec advisories, on pushes too. Unmaintained crates fail the check only when Adeline depends on them directly (`unmaintained = "workspace"` in `.config/deny.toml`).

## Artifacts

The build jobs upload each zip as is (`archive: false`), so the downloaded artifact is the release zip.
